# Optional album.nfo update plan

Status: implemented on November 3, 2026 on local branch `update-nfo`. The [writing guide](tag-writing.md#optional-albumnfo-updates) describes usage, and [VALIDATION.md](../VALIDATION.md) records local validation and pending platforms. This document preserves the delivery design. No branches were created and no changes published.

Subsequent correction: scope was extended to `track/title` after reproducing “To War! → To War!2” in an NFO track list. The first delivery only synchronized general album data. Writing now preserves XML declaration separation and does not add `albumArtistCredits` to documents without it. Direct `artist` elements are preferred over redundant simple credit blocks, repairing NFOs generated by the first delivery; enriched credits are preserved. Repair also separates a joined header. Workflow validation identified cross-platform path differences: catalog-stored POSIX spelling is used to query Windows roots, and normalized physical paths operate on aliased roots on macOS.

## Expected result and scope

When executing **Write tags…** or **Write tags for the entire catalog…**, check for `album.nfo` in each target music file's folder. If present, update album data from the saved catalog. Absence is normal: do not create the file or show an error; continue writing tags. **Save** continues to affect only the catalog.

This proposal assumes metadata XML NFOs with an `<album>` root, compatible with [Kodi conventions](https://kodi.wiki/view/NFO_files/Albums) and its [album template](https://kodi.wiki/view/NFO_files/Templates#album.nfo_Template). The repository contains no NFO examples for checking other formats. Text, URL, combined NFOs and unsupported structures are preserved and produce an explanatory issue. No conversion is attempted.

The initial search is limited to `album.nfo` in the audio folder, respecting filesystem naming rules. Parent folders are not searched: an NFO above disc subfolders is outside this delivery. This avoids automatically associating a different album by proximity.

The check runs even when music tags already match the catalog: an outdated NFO must be repairable without rewriting audio. Each NFO path is processed once per operation.

## Data and album resolution

Selection determines which folders are examined. Album values come from all cataloged tracks in each folder, including unselected tracks. This query does not expand audio write targets. Neither the first song nor the last processed file is authoritative.

| Data | Proposed rule | XML destination |
| --- | --- | --- |
| Album | All folder records must have the same saved value | Direct `album/title` |
| Year | All must agree, including absence | `year`; also update the year in existing `releasedate` |
| Genres | Union without exact duplicates, ordered by relative path and each list's order | One direct `genre` per value |
| Album artists | Use matching `album_artists` credits; if all lack them, accept track artists only when identical across all songs | `albumArtistCredits/artist`; update existing `artistdesc` |
| Song title | Update only target songs uniquely matched by position and disc | `track/title` in an existing list |

Do not split names on separators or equate case, spaces or variants. A consistent empty value removes its managed element; do not invent a year or artist. If album artists are absent and track artists differ, preserve existing NFO credits: this may be a compilation. Other fields can still update.

Incompatible titles/years, conflicting album credits or uncataloged audio preventing composition checks preserve the entire NFO and record a conflict. Do not mix albums or automatically import new tracks. Uncataloged audio detection reuses the project's FLAC/MP3 recognition.

For `releasedate`, preserve month/day if changing the year yields a valid date; otherwise use the year alone. An empty year removes `year` and `releasedate`. Preserve `originalreleasedate`, which has different semantics. Date mappings are fixed in tests using variants of the cited template.

Identifiers and enriched credit data must not be reassigned to another artist. Preserve them when names match; if a change would associate an existing ID with another name, leave the NFO intact and record a conflict. Do not invent IDs.

## XML modification and preservation

Create an NFO adapter independent of Mutagen. Parse the document and modify only managed elements, distinguishing direct album children from same-named nested elements. Add missing managed fields when a value exists and avoid duplicate scalar fields.

Preserve reviews, labels, identifiers, images, ratings, unknown fields, attributes, comments and processing instructions. Do not rebuild the document from a template. In existing track lists, update target song titles while preserving other data, order, numbering, durations and lyrics. Without a unique position/disc match, record a conflict. Content preservation is semantic; writing may normalize escaping and XML representation. Preserve declared encoding, BOM and line endings where supported by serialization; reject unsupported encodings.

Limit input to 16 MiB, reject DTD and entity declarations, and do not resolve external resources. Empty, malformed XML, other roots or structures that cannot be preserved remain intact and are reported as issues. Without semantic differences, retain exact NFO bytes and timestamps.

## Integration with recoverable writing

The existing flow prepares songs in `PreviewTagWrites`, publishes and confirms each audio file in `WriteTagWrites`, and removes backups after success. `TagWriteService.execute` also returns immediately when there is no audio to write. These points must be adapted together for NFO-only operations.

1. Prepare audio differences and discover/group NFOs from all target folders. Snapshot contributing values, folder composition and existing document fingerprints.
2. Log audio and NFO jobs under the same operation before publication. Each NFO has a path-based identity without an invented `file_id`.
3. Keep existing music-file publication and confirmation.
4. Process each NFO once after its target audio files. Publish only if all are confirmed or unchanged. Failures, conflicts, exclusions, catalog-pending states or cancellation in the group leave its NFO pending. Independent groups may continue unless a fatal error occurs.
5. Revalidate aggregated music values and folder composition before publication. Compare business values: audio confirmations change `raw_tags` and may change internal identities without invalidating the intended album.
6. Create and verify an exclusive NFO backup, edit a temporary copy in its folder, reopen it and verify changes, unrelated content and attributes.
7. Revalidate original identity and hash, record the final hash, sync and publish by same-volume replacement. Record whether replacement occurred even if a later check fails.
8. Finalize the combined report and clean up backups only after audio and NFO completion without issues or cancellation.

Apply existing imported-root, symlink, junction, hard-link, permission and attribute-preservation restrictions to NFOs. Reuse file primitives through generic contracts without pretending the NFO is audio. Include its size in space reservation and use backup/temporary names that cannot collide with music files. An NFO appearing, disappearing or changing after preparation is a conflict; never silently overwrite it.

An NFO failure preserves original bytes if not yet published, retains batch backups and permits other albums to continue. Already written audio keeps its actual result. There is no combined transaction or automatic rollback. Lost log/catalog access and essential storage failures still stop pending jobs.

## Contracts, log and interface

| Component | Planned change |
| --- | --- |
| `domain/tag_write.py` | Add NFO plans/results and a separate report collection while preserving music results |
| `application/write_tags.py` | Aggregated reading and NFO codec contracts; per-folder coordination, NFO-only operations and combined finalization |
| `application/album_nfo.py` | NFO aggregation, preparation, publication and technical review through contracts |
| `application/tag_write_errors.py` | Shared music/NFO errors, re-exported by `write_tags.py` for compatibility |
| `infrastructure/album_nfo.py` (new) | Parsing, differences, XML editing and preservation verification |
| `infrastructure/tag_write_catalog.py` | Query and revalidate every folder track's values, including album credits |
| `infrastructure/tag_write_files.py` | Shared primitives, NFO backup/publication, logging and combined cleanup |
| `startup.py` | Compose the new adapter in the service |
| `interfaces/gui/tag_write_dialog.py` | Describe optional updates, show NFO progress/results and allow retry after failure |

NFO results distinguish updated, unchanged, absent, pending, conflict and failed, with path, reason and backup. Include them in output, JSON reports and completion calculations without fictitious song rows or counting them as written audio. Absent and unchanged are successful outcomes. Errors use the existing export popup.

Version the `journal.json` extension and support older logs without NFOs. Store expected values, fingerprints, paths, states and each NFO's publication result. Extend `ReviewTagWrites` to distinguish intact original, verified publication and conflict; review still does not rewrite or restore files. Failed NFOs prevent marking an operation fully resolved or removing pending backups.

Retry rebuilds the plan from current state. Matching audio is skipped and only the NFO is corrected. No SQLite schema changes are required.
